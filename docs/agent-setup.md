# 给AI的接入指南

用户说“帮我把这个项目接上MCP”时，可以按以下顺序执行。范围是用户自己的电脑与已授权AI客户端；保留现有配置，避免把“写好了配置”误报为“接通成功”。

## 1. 核对环境

- 确认当前AI能操作本机文件与命令，定位其真实MCP配置格式。Codex用TOML，Claude Desktop/Cursor通常用JSON。
- 检查Node.js版本（22+）、下载目录及客户端能否正常启动。先执行客户端的基础状态命令；已有配置解析错误要单独报告，不能归因于眼。
- 复用已有WxLens：优先读取用户明确提供的程序路径或原MCP中对应的非敏感启动路径；再检查常见安装位置。不要无界扫描硬盘，也不要读取微信数据库或密钥。
- 查询本机健康接口。`/api/health`可返回`{"status":"ok"}`；业务读取仍采用`{"ok":true,"data":...}`。健康成功不证明账号索引已就绪。

## 2. 安装与一次性初始化

- 有WxLens时可用源码包并运行`npm ci --ignore-scripts`；缺少它时用Windows整合包。
- 运行`setup.cmd`或`npm run setup`。交互式安装器和微信登录/扫码/取钥由本人确认和操作，AI不要求用户把密钥粘贴到对话里。
- 自定义程序位置用`config --wxlens-exe`明确保存。附件目录仅在附件功能需要时配置，多账号必须选择。

## 3. 合并MCP配置

- 用`mcp-config --client codex|json|proma`生成实际绝对路径；添加一个`yan`服务，保留已有其他服务。
- 遵守客户端配置写入权限和重载要求。客户端支持仅本次运行覆盖时，可先临时验证再做用户授权的持久合并。
- 若客户端旧配置有未知字段或类型错误，先备份并明确修正范围，不用不兼容的整份模板覆盖。
- 模型认证必须沿用该客户端与相应提供商的原有认证方式。不能因临时忽略配置就误用另一账号/分组；404“模型不可用”属于模型服务检查项。密钥不写进MCP示例、命令参数、日志、公开报告或仓库。

## 4. 按层验收

1. MCP初始化成功，发现26工具；提示词和资源是可选增强。
2. AI实际调用`list_sessions`，仅列少量目标类型会话。
3. 经用户授权，读取一个目标会话的一条消息。没有记录时如实报告，不自动扩大范围。
4. 确认返回内容和来源字段有效，区分工具错误、空结果和扫描未覆盖。
5. 报告实际客户端、是否临时配置、成功工具及未覆盖范围。不要把少量读取成功扩大成26工具全部真实验收或多群长期运行成功。

## 已有实测（2026-09-14）

Codex CLI 0.144.1实际加载眼并调用`list_sessions`返回2个群，再调用`get_recent_messages`返回1条非空消息；独立MCP SDK客户端同样通过。测试使用临时客户端配置，未改其全局配置，认证由已有模型提供商配置提供。私人群名、ID与正文没有进入仓库。

该实测基于已完成初始化的本机WxLens，不能代替全新电脑扫码/取钥验收、所有AI客户端配置写入验收，或长期多群监控可靠性测试。
