# 旧组件故障与保配置恢复

截至 2026-10-19（Asia/Shanghai），此页适用于旧 Windows 整合包安装的 WxLens 4.3.0 启动白屏、5032 无监听，以及原生 `InitProtection=-101` 的情况。

## 已知问题与处理状态

收到的故障报告显示，旧固定安装器中的 `wcdb_api.dll` 返回 `InitProtection=-101`，随后 `wcdb_init=-1000`，内部日志出现 `expired: self-destruct triggered`。这支持“组件保护层拒绝初始化”的结论。是否固定60天、从何时起算、是否绑定机器，以及错误码的正式定义，仍需要组件提供者确认；报告中的日期关联不能单独证明完整的授权规则。

眼源码的安装与整合打包入口现已停止准入这个固定安装器，错误码为 `YAN_INSTALLER_WITHDRAWN`。该策略按已审阅的固定安装器清单执行，改文件名不能恢复准入。旧文件 SHA-256：

```text
75fffb0b8226b68a5a3e3c17ad9b01d28945eb53ae59f647c49bb82fdd11567e
```

文件哈希相同只说明还是同一个安装器，不说明组件仍然可用。更新眼源码可以获得这项门禁和恢复指引，不能续期或修复第三方 DLL。历史下载包和旧 setup 脚本也不会因新源码改动自动更新；历史整合下载需在 GitHub 发布页另行停用，以实际资产为准。

## 在故障电脑上操作

1. 保留原程序、原组件用户配置和微信数据，不卸载、不清空初始化、不把密钥发给 AI 或其他人。按提供者说明为配置做仅本机的备份；不要覆盖原备份。
2. 在眼目录运行 `node src/cli.js doctor --native`，记录状态、错误码、DLL 哈希和组件版本。只分享诊断元数据，不分享账号目录、配置内容或聊天正文。若不能使用新版源码，可用报告中已有日志交给组件提供者核对。
3. 向组件提供者索取可用的新构建或正常续期方式，并确认适用微信版本、完整 SHA-256、组件有效期、升级/迁移步骤及使用许可。其他电脑的使用和公开再分发许可分别核对。不要从现有机器单拷 DLL，也不要用本机试用成功替代新机器验证。
4. 按提供者支持的方式升级或隔离安装，保留原配置和原程序身份。已有初始化先由原组件迁移，不能保证跨 Windows 用户/机器的受保护配置可以直接复制；迁移不支持时由提供者给出方案，仅缺少首次初始化时再按其界面处理。
5. 将眼指向实际的新程序位置，先验收原生初始化，再验收真实查询。以下路径是占位符，请替换为实际位置：

```powershell
node src/cli.js config --yan-exe "D:\实际安装目录\WxLens.exe"
node src/cli.js doctor --native
npm run verify:live -- --query
```

`doctor --native` 不触发后台服务启动，因此在服务尚未启动时，它可能同时报告“原生通过、服务离线”。下一条 `verify:live -- --query` 才会尝试后台启动并读取至多2个会话；以 `sessionsVerified=true` 和 `ok=true` 为该次小量会话验收依据。只有 HTTP 5032 在线或 MCP 握手成功都不足以证明可读。

消息读取需要另行选择本人授权的一个会话和一条消息。内置 `--query --messages` 只尝试首个会话；空样本或正文不完整时会明确失败，不能为了通过而扩大扫描。验收脚本只输出计数，不输出聊天正文。

## 当前可用证据的范围

2026-10-19，本机眼源码4.1.9使用既有4.7.2组件，正常认证/原生初始化及2会话真实查询通过。该组件初始认证截至2027-01-01 00:00（UTC+8），已有许可只支持本机试用，尚未纳入公开整合包。本机通过不代表报告对应的其他电脑已经恢复，也不代表组件永久有效。

恢复闭环须在故障电脑上完成：提供者交付可用组件或续期 → 保配置迁移 → 原生初始化通过 → 小量会话读取通过 → 按需消息验收。在取得可用组件之前，该电脑的读取恢复应记为阻塞。
