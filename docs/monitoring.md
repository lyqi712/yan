# 多群关注、恢复和定时运行

关注列表是可在不同 MCP 客户端共享的本机状态，不依赖 Proma。配置、调用和结果确认都通过标准 MCP 工具完成。眼不会自行启用定时器或发送通知。

## 创建与修改

```json
{
  "id": "work-groups",
  "name": "工作群交付动态",
  "session_ids": ["group-a", "group-b"],
  "keywords": ["验收", "延期", "报价"],
  "match_mode": "any"
}
```

交给 `configure_watchlist`。最多 10 个会话、30 个关键词，可用 `sender_ids` 同时限制发言人。ID只允许小写字母、数字、短横线和下划线。`list_watchlists` 查看配置及待确认批次。

修改既有列表时显式传 `replace=true` 和完整配置；`paused=true` 暂停。修改会重建基线，避免用旧筛选规则解释新结果。存在待确认批次时，先处理并确认；当前不提供隐式丢弃或删除工具。

## 第一轮和后续轮询

`poll_watchlist({"id":"work-groups"})` 首次默认建立当前基线，不交付早于启动的历史。它会读完基线所在的一整秒，避免同秒记录跨页后被误判。`include_initial=true` 可主动交付首次历史扫描，较长历史分批继续。

后续轮询只处理指定群，逐群检查到上次确认时间边界，并读完同秒区间。对同秒记录按稳定标识去重，不假定 localId 的排序。群的结果包含：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `baseline` | 首次基线已读完 | 确认批次 |
| `checked` | 已覆盖上次确认边界 | 整理后确认 |
| `baseline-building` | 基线同秒区间或指定初始历史仍未读完 | 确认已读批次，再继续poll |
| `catching-up` | 新增超过本轮预算，正在追赶 | 确认已读批次，再继续poll |
| `error` | 上游失败、身份缺失、顺序变化或锚点无法定位 | 本群进度不变；解决问题后继续poll |

每群默认扫描 1000 条，最多 5000 条；全轮最多 20,000 条。续扫会回读有限重叠区找到上一轮尾部锚点。追赶期间头部继续新增的消息，在本次追赶完成后下一轮补取。上游删除、顺序变化或大量位移导致锚点不见时，会保留原进度并报错，不假装追赶完成。

## 消息交付与确认

1. `poll_watchlist` 返回 `batchId`、第一页消息和 `delivery`。
2. `delivery.complete=false` 时，把 `nextOffset` 传给 `read_watchlist_batch`。
3. 按顺序读完所有页，完成用户所需的总结或可靠保存结果。
4. 调用 `ack_watchlist_batch`，参数为列表 `id` 和 `batch_id`。

每页最多 500 条，不能跳过未读分页确认。重复poll始终返回同一未确认批次；重复ack是幂等的。确认会保存已交付的追赶进度；只有读到旧边界后才提交新的确认检查点。失败群不会跟随成功群推进。

`per_session_limit`范围为2–5000，至少保留续扫锚点后继续读一条的预算；建议使用默认1000。

监控保留每条消息的完整 `content`，并记录 `contentChars`、`contentBytes`。眼侧不再按 2000 字符切片；`contentTruncated=true` 以及 `contentComplete=false` 表示 WxLens 自己报告截断、长度不一致或正文未解码，这时不能把批次当作完整正文，必要时用 `get_message_by_id` 或搜索索引回查。来源字段保留，省略无关的上游附加字段。批次状态保存前有 16MiB UTF-8 限额，超限整轮不保存、不推进进度，也不会改成保存截短正文；降低 `per_session_limit` 后重试。单次追赶最多保留 50,000 个消息标识，超限需缩小范围或显式重建基线，不能无限增长。稳定 `localId`/`serverId` 优先作为监控身份；旧状态升级时兼容旧正文哈希，可能出现一次可识别的重叠。

## 本地 CLI

```bash
node src/cli.js watch work-groups --interval 60 --runs 3
```

上例最多运行3轮。默认 `--runs 1`，仅一轮；`--runs 0` 表示明确持续运行。间隔最短30秒。每轮先把完整分页写入 `.local/receipts/`，刷新到文件系统，再确认批次。标准输出只显示批次摘要与文件位置，私人正文保存在本机文件内。

Ctrl+C 停止后不会清空历史批次。若程序在文件写入与ack之间中断，可能留下重复结果文件；可以按 `batchId` 去重。程序不会安装系统计划任务，也不会从 MCP 进程暗中派生后台服务。

## 故障处理

- **MCP断开**：重新连接后poll，继续处理同一未确认批次。
- **某群离线**：查看 `groups[].error`，其他群仍可交付；本群检查点保持。
- **服务或账号改变**：轮询拒绝混用旧来源，使用显式配置修改重建基线。首次切换前先处理旧批次。
- **多个AI同时操作同一列表**：本机文件锁防止覆盖。等待另一操作完成后重试。
- **异常退出留下 `.lock`**：关闭所有眼的MCP/CLI进程，确认没有活跃操作后，手动移除 `.local/watchlists/<id>.json.lock`。不要在进程运行时移除锁。
- **状态文件损坏**：保留原文件用于排查；不要假称可恢复完整进度。重新创建不同ID的列表会建立新基线，可能出现重叠或历史空白。

## 适用边界

这是有来源和可重试的索引轮询，不是数据库事务日志。依赖 WxLens 提供最新在前的消息排序；对实际读取窗口验证时间非递增。同秒会读完整区间，但更早时间的迟到索引和历史回填不保证发现。消息在扫描过程中被删除或重排时，也不能宣称全量准确。需要严格留存时，保留原始语料并结合来源校验。

`.local/` 包含明文批次、群标识和规则；请使用操作系统账号和磁盘权限保护，不把该目录放到公共同步盘。分享聊天内容属于独立操作，眼不会自动代表用户发布。
